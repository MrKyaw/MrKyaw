# Contributing

Thanks for your interest in improving this project.

## Reporting bugs and requesting features

- Open an issue with a clear title, expected behavior, actual behavior, and reproduction steps.
- Include environment details (OS, runtime, versions) and relevant logs where possible.
- For security issues, **do not open a public issue** — follow [SECURITY.md](SECURITY.md).

## Pull requests

1. Fork the repository and create a focused branch.
2. Keep changes small and scoped to one concern.
3. Add or update tests and documentation where behavior changes.
4. Use clear commit messages in the imperative mood.
5. Open the PR with a short description, linked issue, and validation steps.

## Code style

- Follow the conventions already used in the repository.
- Keep functions and modules readable; prefer clarity over cleverness.
- Do not commit secrets, credentials, or personal data.

## Review

Maintainers may request changes. Please respond to review comments and keep the branch up to date with the default branch.

## Code of conduct

Be respectful, constructive, and professional. Harassment and discriminatory behavior are not tolerated.
